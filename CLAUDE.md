## The system (4 repos, one product: "EduManage" school management — names say "shelfwatch", it is NOT retail)
| Repo (on disk) | What | Stack |
|---|---|---|
| `IRCTC_Clone/shelfwatch_sfa_ir_backend` | REST API, source of truth for rules (own CLAUDE.md) | FastAPI, PyMySQL raw SQL, MySQL/TiDB, Alembic |
| `IRCTC_Clone/shelfwatch-plus` | Admin/staff web app for one school (own CLAUDE.md) | Vite + React 18 + Tailwind, plain JSX |

**Multi-school**: the backend serves many schools ("organisations"); every login names a school code and data never crosses schools (backend `docs/ORGANISATIONS.md`).

## Architecture (no navigation library, no state library)
- `index.js` → `src/App.tsx`: boot (loadSession + loadLang + loadUiTheme) → Login (school code + username + password) / ForgotPassword (school code + username/email) / ForcedPasswordChange, else a home screen + a push stack. `navigate(route, params)` pushes, `goBack()` pops, Android back pops. Stack resets when the user changes.
- `src/routes.ts` — `SCREENS` registry `{component, title | titleKey, transition?, ownHeader?}` (`ownHeader`: the screen draws the portal header itself, App.tsx skips its top bar and paints the status strip brand); `homeForRole`: student → `HomeStudent`, everyone else → `HomeStaff` (themed switcher; launcher list `GRIDS` picked by role: teacher / driver / manager; admin+principal = "top manager").
- `App.tsx` `navigate(route)` also calls `markSeen(route)` and `goBack()` marks the popped route seen (red "new" dots, below); on sign-out the session listener calls `resetUiTheme()`.
- `src/components/ScreenStack.tsx` animates routes that opt in (`transition: 'fadeScale'`), keeps the home (`persistentKey`) mounted under pushed screens, and tells each screen whether it is on top (`useScreenActive` / `useOnReturn` in hooks.ts).
- Every screen gets `ScreenProps {navigate, goBack, params, session, onLogout}` (`src/types.ts`, which also holds all API response types).
- Navigation: home (orbit checkpoints or classic tiles, below) → pushed screens. New screen = file in `src/screens/` (staff ones in `screens/staff/`) + entry in `SCREENS` (student screens wrapped in `themedScreen`, see "UI themes") + a launcher entry in the home's list (student: `STUDENT_MENU` in `screens/home/useStudentHome.ts`; staff: `GRIDS` in `screens/staff/home/useStaffHome.ts`) (`{icon, label, sub, route, params?}`) + a tile colour in `components/HomeTiles.tsx` `TILE_COLORS` + (if it has "new" content) its section in `updates.ts` `SECTION_OF_ROUTE` and the backend's `services/updates.py`.

## Data layer — layers: screens → `api.ts` → `session.ts` → `http.ts`
- `http.ts` `send()` — fetch + timeout, sends `X-Device-Id` (`device.ts`: random install id in AsyncStorage `sw_device_id`, kept after sign-out; the server throttles sign-ins per account + device), turns errors into `ApiError{status (0 = network), detail, requestId, retryAfterSec, code}` (`code` = body `code`, e.g. 428 `captcha_required` / `captcha_invalid`) with a ready-to-show message; `errorText(e)`.
- `session.ts` — access token in memory only; refresh token in `tokenStore.ts` → **`secureStore.ts`** (react-native-keychain = Android Keystore; ONE keychain item `edumanage.secure.v1` holding a small JSON of secrets: `refresh_token`, `cache_key`; one Keystore read per cold start). Builds before late Oct 2026 kept the token in AsyncStorage `sw_app_refresh_token`: it is moved into the keychain on first read (nobody is signed out). If the keychain fails on a phone, `secureStore.set` returns false and the token goes to that AsyncStorage key as before (read first: it is only there when newer). Session (incl. `org_code`, `org_name`) in AsyncStorage `sw_app_session`; last school code in `sw_last_org_code` (kept after sign-out; `getLastOrgCode()`). Single-flight `refreshTokens()`, refresh on app resume, refresh 401 → `endSession('expired')` (clears every secret). `onSessionChange` drives App.tsx.
- `api.ts` — `api(path, opts)` authed request (auto refresh+retry on 401; 403 "Password change required" → forced change screen), `apiPage(path, limit, offset)` → `{items, total}` from X-Total-Count, `withQuery`, auth calls (`login(username, password, orgCode?, captcha?)` always sends `captcha_supported: true`; after a few failures the server answers 428 → `needsCaptcha(e)` → `getCaptcha()` (`POST /auth/captcha` → `{captcha_id, image: data URL, length}`) → next `login(…, {id, answer})`; each picture is good for one try. Login.tsx shows it (`testID login-captcha`). Logout, logoutAll, changePassword, forgot/verify/reset — `orgCode` is the optional arg; sent as `org_code`), `lookupSchool(code)` (public `GET /organisations/{code}` → `{code, name}`), `photoUrl()` (signed URLs expire 24 h — never store them).
- `cache.ts` — stale-while-revalidate: every GET is remembered per user in memory (20 h max, 80 entries); screens seed state with `peek(path)`. **On disk (late Oct 2026):** responses matching `SCHOOL_WIDE` (timetables, holidays, calendar, notices, events, syllabus, documents, classes, exams list, stats, school settings, updates…) as plain JSON in AsyncStorage `sw_app_cache_v2`; **everything else (personal: driver routine, students, users, profiles, fees, marks, messages, salaries…) only ENCRYPTED** in `sw_app_cache_secure_v1` (`cryptoBox.ts`: XChaCha20-Poly1305 via @noble/ciphers; key in secureStore `cache_key` = `<owner>|<base64>`; key from `crypto.getRandomValues` or, on Hermes without it, HKDF over the refresh token + clock), newest first up to `MAX_SECURE_CHARS` 120K (rest memory only). No secure storage → personal responses memory only. New endpoints are personal unless added to `SCHOOL_WIDE`. Saves: plain 1.5 s after a change, encrypted 6 s, both at once when the app goes to the background (`flushCache`). The old plain `sw_app_cache_v1` is read once (no cold-start loss) and re-saved split. Cleared on logout / new login (new key per login).
- `hooks.ts` — `useApi(path)`, `usePagedApi(path)`, `useOnResume`, `useI18n`, `useUiTheme`, `useUpdateDots`, `useReduceMotion`, `useSchoolTimings`, `isMissingEndpoint(e)` (404/405 → "needs server update" fallback).
- `notifications.ts` — unread count polling + `onUnreadChange`, markRead/markAllRead, `targetOf()` maps a notification to a route. Polling (late Oct 2026): only while the app is in the foreground (`appEvents.ts` `onAppBackground` stops the timer, resume re-reads at once), every `POLL_MS` 60 s, or `POLL_WITH_PUSH_MS` 5 min once push.ts registered the device (`setPushActive`; a foreground push re-reads at once). `push.ts` — FCM; packages are in package.json (v26 = **modular API only**: `getMessaging()` + functions, no default export — push.ts wraps it); **push is ON**: `config.ts PUSH_ENABLED = true`, `android/app/google-services.json`, google-services Gradle plugin, POST_NOTIFICATIONS in the manifest. `index.js` calls `registerBackgroundPushHandler()`; debug builds log `[push] FCM token: …`. **Enable + test step by step: `docs/TESTING_PUSH_NOTIFICATIONS.md`** (Firebase console, token, console test message with custom data `route`, foreground = bell only / background / killed = tap opens `route`, iOS, troubleshooting).
- `updates.ts` — red **"new" dots** on the home launchers (all roles, both themes). `GET /updates` (backend `services/updates.py`) → `{server_time, sections: {key: {latest_at, unread?}}}`; `SECTION_OF_ROUTE` maps launcher routes to keys (student: Homework, Notices, Messages, StudentTimetable→timetable, Syllabus, Events, Attendance, Fees, Exams, ReportCards, Holidays, MyTransport→transport; staff: StaffNotices→notices, MyTimetable→timetable, Substitutions, Leaves, Salary, FeeClaims). "Last opened" per section is kept per device + account in AsyncStorage `sw_seen_v1:<org>:<role>:<id>` (**kept after sign-out**; server time via `server_time` offset); dot = `latest_at > seen`. A section never opened here counts only the last `NEW_WINDOW_DAYS` (7). Checks: `startUpdates(owner)` at sign-in/cold start (App.tsx), `refreshUpdates()` in the homes' load (pull-to-refresh, return to home, resume). `markSeen(route)` from App.tsx navigate/goBack. 404/405 → no dots. Hook `useUpdateDots()` → `{hasNew, version}` (put `version` in the deps of memoised launcher lists).

## Home screen — night-sky "orbit" (`src/components/orbit/`, used by HomeStudent.creative + HomeStaff)
Built for smoothness — keep it that way (no JS per frame, nothing re-rendering while it moves):
- `OrbitHome` = `SceneBackground` (sky + school-on-the-hill pictures, twinkles / shooting stars / fireflies; memo, **paused while the home is covered**) · `OrbitMenu` (full screen, memo) · header top-left (`HomeParts`: greeting + compact today panel; pull-to-refresh; width = screen − `L.headerGutter`, max height `HEADER_H` 240 × font scale) · `Bell` (Notifications + unread badge, re-renders on its own). Props: `header, items, onNotifications, refreshing?, onRefresh?`. **Screens must pass a `useMemo`'d `items` list** (keyed on the figures shown + `lang`) so the orbit doesn't redraw when only the header changes.
- **Static scene** (`OrbitScene`, memo): ONE picture `assets/home/orbit_scene.webp` (723×1280, ~136 KB) = night Earth (real coastlines + city lights, axis tilted **23.44°** + 18° toward the viewer, no rotation) + atmosphere + dashed axis + protractor + chalk-dashed Equator / Tropics + the curved stretch of the orbit line. The app adds only 2 gradient rails (4 views) and translated text (Equator / Tropic names, "23.44° axial tilt"; positions from `globe.ts`). Regenerate with `tools/earth/texture.py` then `render.py` (`pip install global-land-mask scipy pillow numpy`); keep `PATH_R / FILLET / RAIL_DX / BOX_*` in render.py in sync with `geometry.ts` and `TILT / BETA` with `globe.ts`. (Math file is `globe.ts`: macOS is case-insensitive.)
- **Path** (`geometry.ts`, pure, tested): ONE path, mirror-symmetric about the Earth's centre line — top rail → fillet → arc round the left of the Earth → mirrored fillet → bottom rail; both ends off screen. `orbitLayout(w, h, count, headerH)` samples it (`ss/xs/ys`), places the Earth (partly off the right edge), picks `step` (≥ 112 dp × s, a short list spreads over the whole path; ONE checkpoint per screen, `slots` = count, `cycle` ≥ path length, so no screen ever appears twice — the extra ones wait on the hidden stretch and the scroll still loops) and the scroll mapping (`home`, `scrollStart`, `scrollHeight`, `progressAt`).
- **Motion = a native ScrollView.** An invisible `Animated.ScrollView` over the orbit area: its offset feeds ONE `Animated.Value` via a native `Animated.event`; every checkpoint's translateX/Y (and the dot after it) is `interpolate(mod(progress + j·step, cycle))` over the path samples (`pathTables`). Drag, fling and snapping (`snapToInterval = step`, a checkpoint rests on the arc's left-most point) run on the UI thread. Checkpoints only translate — no scale/opacity. JS hears only scroll **start/end**: at rest it records the offset, updates which checkpoints are on screen (a11y), and hit-tests taps (`onTouchStart/End` + `hitTest`; tap the Earth = one stop). Huge content height (±2000 steps) makes the loop endless.
